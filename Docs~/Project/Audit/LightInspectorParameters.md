# Light Inspector parameter audit

The November 2024 reference is the directional-light reconstruction from `b610fb26`. Its source draws Color and Intensity together, followed by Temperature and the Diffuse and Specular sliders. General, Emission, Indirect Lighting, Mask, Shadow and Volumetric Fog have a single foldout each. Local lights also have Performance. The historical `LightComponent` authored both Unity-facing and Infinity-only values.

The current panel keeps the compact Color and Intensity row and uses one foldout per section. Right-hand float inputs retain precision and the existing property domain. The ranges on weights, indirect and volumetric intensity, and shadow bias define the slider's travel. The owners of emission, shape, lighting masks and shadows are defined in [Lights](../../../ARCHITECTURE.md#9-lights).

| Current Inspector fields | November 2024 comparison | Current value and its consumer |
|---|---|---|
| Type and Spot Shape | Type already existed. Cone, Pyramid, Box and the separate Disk type came with the later shape model. | Infinity shape chooses the analytic model and derives the Unity type for culling. Disk uses a Rectangle carrier with the same emitting area and retains its disk geometry for shading and baking. |
| Sun Diameter | The Directional panel called its Infinity field Radius. The later model explicitly uses a full diameter in degrees. | Infinity `sourceAngle` drives the realtime disk and baked penumbra. The native Unity `shadowAngle` is derived from it for authored lights. Unauthored lights read Unity's native angle. |
| Extra Spread and Extra Radius | Neither control existed. Both fields entered in S6, commit `834f41de`, on 2026-10-12. The older PCSS Min and Max Softness were separate shadow controls. | Infinity-only `softSourceAngle` and `softSourceRadius`. The light record packs the angle as `tan(angle / 2)` and the radius in meters. The BRDF and PCSS combine each with the physical extent. The lightmapper and the native carrier derive from the physical shape. |
| Source Radius and Length | Point and Spot already had Radius. Point already had Length. | Infinity derives Sphere, Line and Tube from radius and length. It publishes the derived native type, applicable native radius and tube length. Range has its own meaning. |
| Source Width and Height, Aspect Ratio, Box Width and Height, Barn Doors | Rect width and height already existed. Aspect ratio, box dimensions and barn doors came with S6. | Infinity owns all of these. Rect, Pyramid and Box publish their supported extents to Unity. Barn Doors shape the realtime rectangle emission. |
| Color, Intensity, Use Temperature, Color Temperature | The old color and intensity shared a row, and the old path enabled temperature unconditionally. | Native `Light` owns the four fields. Culling supplies the combined `VisibleLight.finalColor` to realtime code. Baking uses Unity's light extraction. |
| Range, Outer Angle, Inner Angle | The old component exposed range and both spot angles. | Native `Light` owns these values so Unity culling, the lightmapper and Infinity agree on the projection. The record builder uses outer angle for Cone and Pyramid and inner angle for Cone. |
| Diffuse Weight, Specular Weight | Diffuse and Specular were in Emission as 0–1 sliders. | Infinity weights multiply the corresponding surface-lighting terms. |
| Baking Mode and Indirect Multiplier | State mapped Dynamic, Mixed and Static to Unity bake modes. Indirect Lighting exposed Enable and Intensity. | Native bake mode controls participation. The indirect multiplier comes from Unity's bounce intensity at extraction. The historical separate enable bit has no current Inspector counterpart. |
| Cookie, Cookie Size, IES Profile | Mask exposed Cookie and IES Texture. Directional extent is explicit in the current panel. | Unity provides Cookie and directional cookie size. Infinity owns the IES profile. The light context validates the dimensions and packs the projected or directional atlas sampling data. |
| Shadow Mode, Strength, Near Plane, Depth Bias and Normal Bias | Enable and Near Plane existed. Strength and bias are explicit in the current panel. | Native `Light` supplies enable/cast mode and strength. The shadow allocator uses Near Plane in local projections and directional cascade fitting and uses the two biases for caster offsets. |
| Caster Layers, Shadow Filter, Update Mode, Request Shadow Map Rendering and Contact Shadows | Layer, Type and contact enable existed. The old panel also exposed per-light resolution, PCSS limits and contact length. | Caster Layers reads Unity's rendering-layer mask. Infinity owns the filter, local cache update policy and contact flag. The request advances the On Demand cache. The pipeline controls shadow resolutions and contact-shadow settings. |
| Volumetric Enabled, Intensity and Shadow Weight | The old Volumetric Fog category exposed Enable, Intensity and Occlusion. | Infinity writes the volumetric flag and weights. The shading helpers scale volumetric radiance and blend shadow visibility toward unshadowed. |
| Culling Mask and Light Layers | The old Light Layer was in General. | The Unity GameObject-layer mask and rendering-layer mask filter caster candidates. Infinity Light Layers are packed separately for lighting receivers. |
| Maximum Distance and Distance Fade | Performance exposed both values for local lights. | Infinity's camera-distance fade scales light radiance before packing. A nonpositive maximum means unlimited distance. |

Changing one of the extra softness controls into a derived value would change specular and PCSS for any existing light with a nonzero authored value. Such a change requires an explicit choice for those values and a realtime comparison. The current labels describe the two established controls while retaining their serialized fields and math.
